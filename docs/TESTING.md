# 테스트 및 검증 기록

측정 환경: Linux 컨테이너 (4 vCPU, Node 22, Rust 1.97). **Windows GUI는 이 환경에서 실행할 수 없었습니다.**
아래에서 "자동"은 매 CI마다 실행되는 테스트, "Linux 네이티브"는 실제 릴리스 바이너리를 Xvfb(가상 디스플레이, 소프트웨어 렌더링)에서 실행해 확인한 결과입니다.

## 자동 테스트

| 종류 | 명령 | 결과 |
| --- | --- | --- |
| 단위 (필터/정렬/진행률/순서/날짜/검증) | `npm test` | 통과 |
| 통합 (실제 마이그레이션 SQL + SQLite 파일, 재실행 시뮬레이션) | `npm test` | 통과 (2개 파일, 38개 테스트) |
| E2E (빌드 결과물을 Chromium에서 실행, Tauri IPC를 실제 SQLite에 연결한 mock) | `npm run e2e` | 25/25 통과 |
| Rust 창 위치 보정 로직 | `cargo test` | 8/8 통과 |
| 정적 분석 | `tsc -b`, `eslint .`, `cargo clippy -D warnings` | 경고 0 |

통합/E2E로 확인한 항목: Task 생성·수정·완료·복원·삭제·실행 취소, 빈 제목 거부, 잘못된 날짜/우선순위 거부, 필터(전체/오늘/예정/완료), 정렬(직접/마감일/우선순위), 검색, 드래그 및 Alt+↑/↓ 순서 변경과 재실행 후 유지, Plan 생성·수정·날짜·삭제(할 일 유지), Task 연결/해제, 진행률(3/5 = 60%), 설정(테마/항상 위/정렬/마지막 화면) 유지, 재실행 후 데이터 복원, 마이그레이션 재실행 안전성, DB 쓰기 실패 시 데이터 보존 및 재시도, 닫기 직전 입력(debounce 대기 중) 저장, 저장 실패 시 닫기 차단, 200건 연속 추가·완료, 1,000건 로드, Title Bar 드래그 영역이 버튼에 적용되지 않음.

## 성능 측정

### Chromium (WebView2와 같은 엔진) — `npm run e2e`

| 항목 | 100개 | 1,000개 |
| --- | --- | --- |
| 창 표시까지 (첫 렌더 후) | ~50–65 ms | ~60–100 ms |
| 데이터 로드 후 UI 준비 | ~105–120 ms | ~240–310 ms |
| 체크박스 클릭 → 화면 반영 | ~7 ms | ~7–15 ms |
| 할 일 추가 → 화면 반영 | ~14 ms | ~5–12 ms |
| 스크롤 프레임 p95 | 16.9 ms (60fps) | 16.9 ms (60fps) |
| Idle 5초간 스크립트 실행 / 레이아웃 | 0 ms / 0회 | 0 ms / 0회 |
| JS Heap | 4.5 MB | 9.9 MB |

화면 전환(할 일↔계획↔설정) 35회 반복 후 GC 기준 힙 증가 < 0.3 MB (누수 없음).

### Linux 네이티브 릴리스 바이너리 (WebKitGTK, Xvfb, 소프트웨어 렌더링)

| 항목 | 결과 |
| --- | --- |
| 실행 파일 크기 | 5.6 MB (`.deb` 2.56 MiB) |
| 실행 → 창 표시 | 첫 실행(DB 생성 포함) ~430 ms, 이후 ~230 ms |
| Idle CPU (입력창 포커스 해제 상태, 30초) | 모든 프로세스 0 ms |
| Idle CPU (입력창 포커스 + 커서 깜박임, 30초) | ~210 ms (단일 코어의 ~0.7%) — 창이 포커스를 잃으면 커서 깜박임도 멈춤 |
| 메모리 (프로세스 3개 합계) | PSS ~188 MB / RSS ~330 MB — WebKitGTK + 소프트웨어 GL 기준이며 Windows WebView2 수치와 다름 |
| 닫기 버튼 → 종료, 창 위치 저장 | 통과 (`window-state.json` 기록) |
| 재실행 → 위치(1200,300) 복원 + 입력한 할 일 유지 | 통과 |
| 저장 위치 (4200,2500) → 1920×1080 화면 안 (1560,560)으로 보정 | 통과 |
| 중복 실행 → 두 번째 프로세스 즉시 종료 | 통과 (D-Bus 세션 필요, Windows는 Mutex 사용) |

## Windows에서 직접 확인이 필요한 항목 (미검증)

이 환경에서는 Windows GUI를 실행할 수 없어 아래 항목은 **실제로 확인하지 못했습니다.**
GitHub Actions(`windows-latest`)에서 빌드가 만들어지며, 설치 후 다음 체크리스트로 확인하세요.

- [ ] Title Bar 빈 영역 드래그로 창 이동, 버튼 클릭은 드래그되지 않음
- [ ] 창 가장자리로 크기 조절 (테두리 없는 창 + shadow), 최소 크기 300×380 적용
- [ ] Windows 11에서 둥근 모서리/그림자 표시
- [ ] 항상 위에 표시 On/Off
- [ ] 최소화, 작업 표시줄 복원, 닫기(Alt+F4 포함) 시 마지막 입력 저장
- [ ] 다중 모니터: 보조 모니터에 둔 뒤 종료 → 모니터 분리 후 실행 시 주 모니터로 복귀
- [ ] 배율이 다른 모니터(100% / 150%) 간 이동 후 재실행 시 위치/크기
- [ ] 작업 관리자 기준 Idle CPU 0%, 메모리 사용량 (WebView2 프로세스 포함)
- [ ] 설치 프로그램(NSIS/MSI) 설치·실행·제거, SmartScreen 경고(미서명) 확인
- [ ] 한국어 IME: 조합 중 Enter 시 마지막 글자까지 포함해 추가되는지 (조합 이벤트 순서는 E2E에서 시뮬레이션으로만 검증)

측정 방법: 작업 관리자 → 세부 정보에서 `desktodo.exe`와 하위 `msedgewebview2.exe` 프로세스의 CPU/메모리(커밋/작업 집합) 합계를 확인합니다.
